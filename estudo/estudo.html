Guia de estudo

Resumo do código do Shaka (versão React) organizado pra revisão antes da apresentação. Cada seção explica o "porquê" das decisões, não só o "o quê".

// 01

Visão geral da arquitetura

O projeto original (HTML + CSS + JS puro) tinha tudo misturado: um script.js único com variáveis globais e funções que escreviam direto no HTML. Na versão React, cada responsabilidade mora numa pasta:

lib/

Lógica pura — cálculos, chamadas HTTP. Não sabe que existe uma tela.

hooks/

Estado + efeitos colaterais reutilizáveis (login, notificações).

components/

Cada pedaço visual da interface, um arquivo por componente.

App.jsx

O "maestro" — junta tudo e distribui dados pros componentes.

Regra geral da migração

Toda variável global do script.js virou useState em algum componente. Toda função que alterava o DOM diretamente virou uma condição dentro do JSX.

// 02

lib/ — lógica pura, sem tela

Não importam React. Só recebem dados, processam e devolvem um resultado.

lib/supabase.js

Uma função, fazerRequisicaoSupabase(), que monta a URL da REST API do Supabase e faz o fetch. Todo componente que lê ou grava no banco importa essa função.

lib/weather.js

Toda a lógica de clima/vento/ondas que estava espalhada no script.js:

  • WMO_CODES — traduz código de clima em emoji + descrição.
  • grausParaDirecao() — graus viram ponto cardinal com seta.
  • estimarOndas() — estima onda pelo vento quando a API de mar não cobre a região.
  • calcularScoreSurf() — nota de 0 a 10 pras condições de surf.
  • carregarClima(lat, lon) — busca as APIs e retorna um objeto pronto, em vez de escrever direto no DOM como no original.

lib/resumoIA.js

A "IA" é uma análise local por palavras-chave nos comentários — não é um modelo de linguagem. analisarComentariosLocal() conta ocorrências de termos positivos/negativos/de surf/de estrutura e monta um resumo com pontos positivos, negativos, dicas e sentimento geral.

// 03

hooks/ — estado reutilizável

Um hook empacota estado + efeitos colaterais para reaproveitar em qualquer componente.

hooks/useToast.js

Substitui o mostrarToast() original, que criava um <div> no DOM na marra. Aqui só atualiza um useState, e o componente Toast.jsx decide como desenhar.

hooks/useAuth.js

Substitui verificarUsuarioLogado(), autenticar() e logout():

  • Ao montar, verifica localStorage por um usuário salvo; se não achar, gera um id anônimo.
  • autenticar() faz login ou cadastro dependendo do parâmetro modo.
  • logout() limpa o usuário e gera um novo id anônimo.
// 04

components/ — a interface, peça por peça

App.jsx

Componente raiz. Carrega praias e serviços ao abrir (equivalente ao antigo DOMContentLoaded), controla quais modais estão abertos.

Navbar.jsx

Escuta o scroll da página pra saber quando escurecer o fundo. Mostra "Login" ou o avatar, dependendo se há usuário logado.

Map.jsx

A parte mais delicada: Leaflet manipula o DOM por fora do React, então fica isolado num <div> com useRef, e toda configuração roda dentro de useEffect.

BeachDetailsPanel.jsx

Componente com mais estado do projeto: clima, análise, eventos, comentários e resumo de IA. Um useEffect dependente de praia?.id dispara todas as buscas ao trocar de praia.

WeatherWidget.jsx

Só recebe dados já calculados via props e desenha — não faz nenhuma chamada de rede.

ServicosSection.jsx

Grid de serviços com filtro por categoria e busca, recalculados automaticamente com useMemo.

AuthModal.jsx / ServicoModal.jsx

Os dois modais. Guardam os campos do formulário em useState e chamam funções recebidas via props ao submeter.

// 05

Fluxo de dados

React segue um fluxo de cima pra baixo: o App.jsx é dono dos dados principais e passa pedaços deles via props. Exemplo prático — do clique num card até o mapa reagir:

Usuário clica num BeachCard → chama onClick(praia).
Essa função é o setPraiaSelecionada do SpotsSection.jsx.
praiaSelecionada muda → o React re-renderiza o SpotsSection.
O Map.jsx recebe a nova praia como prop → o useEffect dispara o flyTo().
O BeachDetailsPanel recebe a mesma praia → dispara as buscas de clima/eventos/comentários.
Ponto-chave

Ninguém "manda o mapa se mover" diretamente — todo mundo reage à mudança do mesmo dado central.

Perguntas prováveis na apresentação

Por que o mapa não é 100% React?

O Leaflet precisa de um elemento real do DOM pra desenhar tiles e marcadores — não fala a "língua" do JSX. Isolar a lib inteira em useEffect + useRef é o padrão pra integrar qualquer biblioteca assim (mapas, gráficos, editores).

Onde fica o backend?

Não existe um backend próprio — o Supabase cumpre esse papel (banco + API REST).

O que é useState / useEffect?

useState guarda um valor que, ao mudar, redesenha a tela sozinho. useEffect roda código em resposta a algo mudar — busca de dados, integração com libs externas, listeners.

Antes de apresentar

Confirme que rodou npm install e npm run dev dentro da pasta certa do projeto (não da versão HTML antiga), e que o Supabase está respondendo (abra o DevTools → Network e veja se as chamadas retornam 200).
